# 008. Минимальная правка Django-монолита

## Контекст

Монолит выключают через несколько месяцев, поэтому любая правка в нём — расход
с коротким сроком окупаемости. Но полностью не трогать его нельзя:
`/api/tles/` сегодня **только на чтение**, а без записи сценарий уточнения
остаётся ручным до самого переезда.

Обойти можно было бы только записью напрямую в чужую базу — это хуже
по всем статьям.

### Что выяснилось про аутентификацию

Эндпоинта «кто я» в текущем API нет. Но он и не нужен: в монолите стоит
`mozilla-django-oidc` с Keycloak (`network/oidc.py`), а в v2 настроен
`AUTH__KEYCLOAK__*` и `AUTH__JWT__ISSUER`. **Провайдер личности общий**,
поэтому сервис валидирует JWT сам, одинаково до и после переезда.

## Решение

Четыре правки, не больше:

1. `network/base/tle_priority.py` — `"Fitted"` в список источников
   и посточниковое окно свежести (см. [010](010-fitted-priority.md)).
2. `network/api/` — `POST /api/tles/` с проверкой прав.
3. Ссылка на раздел со страницы наблюдения.
4. `location /tle/` в nginx — правка на сервере, не в репозитории.

Эндпоинт записи **переиспользует готовое**, а не пишет заново:
`network/base/tasks.py::validate_tle` (контрольные суммы, согласованность номера,
диапазоны элементов) и `refresh_latest_tle_sets`.

## Отвергнуто

**Ноль изменений в монолите.** Сервис только считает и отдаёт файл, публикация —
руками через админку, автоматическая — после v2. Соблазнительно, но сценарий
уточнения при этом ждёт месяцы, а он и есть основная причина делать раздел.

**Интеграция сразу только с v2.** Не пришлось бы делать адаптер дважды,
но раздел жил бы на стенде до самой миграции.

**Собственный `/api/me/`.** Оказался не нужен — Keycloak общий.

## Следствия

- Фича полностью работает до переезда.
- Правка `tle_priority.py` затрагивает выбор TLE для **всей** сети,
  поэтому требует внимательного ревью, несмотря на малый объём.
- Адаптер к API делается дважды — это принятая цена решения
  [005](005-placement.md).
