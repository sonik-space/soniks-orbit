# 004. Регуляризация к затравке вместо флагов заморозки

## Контекст

В `rffit` оператор цифрами 1–7 решает, какие элементы свободны. Гайд предписывает:
на одно наблюдение — только аргумент перигея, на набор в 2–3 дня — RAAN,
аргумент перигея и среднее движение.

Причина в физике: **из одного прохода наблюдаемы примерно две величины** —
момент наибольшего сближения и крутизна перегиба S-кривой. Шесть элементов
из них не восстановить, и попытка отпустить лишнее даёт правдоподобный RMS
при бессмысленных элементах.

Заявленный сценарий «при сходе с орбиты уточнять по каждому наблюдению» означает,
что однопроходный фит — не краевой случай, а регулярный режим работы.

## Решение

Все семь элементов всегда свободны, но в вектор невязок добавляются априорные члены:

```
r_prior[j] = (a_j − a_seed_j) / σ_j
```

плюс отдельный член на комбинацию `argp + M`, разрешающий вырождение при
околокруговой орбите.

Слабо определённые направления автоматически остаются у затравки, хорошо
определённые уезжают свободно. Один и тот же код работает и на одном проходе,
и на десяти.

Параметризация сразу масштабированная — `p_j = (a_j − a_seed_j)/σ_j` — поэтому
приорный член получается бесплатно, а `x_scale = 1.0`.

## Отвергнуто

**Пресеты по объёму данных плюс галочки.** Сервис предлагает набор по правилу
(1 проход → только argp; 2–3 дня → RAAN+argp+n; больше → +i, +e), человек может
переключить. Ближе к привычному процессу и проще сверяться с `rffit`.
Но правило пришлось бы всё равно кодировать, а на границах оно произвольно —
и в автоматическом сценарии идентификации решать всё равно должен код.

**Только ручные галочки, как в `rffit`.** Сервис ничего не решает за человека.
Не работает в автоматическом сценарии и при ежедневном уточнении при сходе с орбиты.

## Следствия

- Нет ни галочек заморозки, ни правил «сколько параметров размораживать».
- **Априорные σ — калибровочные ручки.** Значения по умолчанию для LEO —
  в [algorithms.md](../algorithms.md); они передаются в запросе и **сохраняются
  в прогоне фита**, иначе результат невоспроизводим.
- Результат больше не совпадает с `rffit` побитово, поэтому режим совместимости
  сохраняется отдельным флагом ради регрессионного теста.
- Фит обязан сообщать, какие элементы **удержаны приором** (сравнение
  `|Δa_j|/σ_j` с единицей), а UI — показывать их иначе. Иначе оператор примет
  затравку за результат: число выглядит так же, но данными оно не подтверждено.
- Член на `argp + M` обязателен: без него при `e ≈ 0` фит хаотично гоняет оба
  параметра в противоположные стороны.
