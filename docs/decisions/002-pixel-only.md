# 002. Источник данных — только пиксели PNG

> **ДЕЙСТВУЮЩЕЕ РЕШЕНИЕ.** Обоснование ниже частично устарело — см. раздел
> «Что изменилось после измерений» в конце файла. Альтернатива с выгрузкой
> артефакта проработана и отложена, см. [011](011-spectrum-artifact.md).

## Контекст

СОНИКС хранит водопад **только как отрендеренный PNG** — `waterfall` в модели
наблюдения это `ImageField`. Сырых спектральных данных сеть не хранит.

Сырые данные при этом существуют на станции: клиент читает файл с заголовком
(`timestamp`, `nchan`, `samp_rate`, `nfft_per_row`, `center_freq`) и строками
`(время, спектр[nchan])`. Его можно было бы выгружать.

### Ключевая находка

**PNG несёт точную калибровку в текстовых чанках.** Проверено на боевом
наблюдении 1527888:

```
satnogs:wf-dat = {"nchan":"1024","samp_rate":"57600","nfft_per_row":"5",
                  "center_freq":"435973500.0","timestamp":"2026-08-16T10:32:52.650048Z"}
```

Полоса равна `samp_rate` точно. Это снимает главное возражение против пиксельного
подхода: старый инструмент **угадывал** полосу (`48e3`, с комментарием
«very bad heuristic, will fail in many cases»), и именно догадка была источником
систематической ошибки, а не пиксели.

### Цифры

| | PNG | Сырой `.dat` | Только «гребень» |
|---|---|---|---|
| Размер на наблюдение (проход 400 с) | 704 КБ | **18.5 МБ** | 36 КБ |
| Разрешение по частоте | 93 Гц/пиксель | 56 Гц/канал | 56 Гц |
| Работает на истории наблюдений | да | нет | нет |
| Изменений в клиенте и сети | нет | да | да |

Типичный RMS фита — сотни герц. Выигрыш 93 → 56 Гц в нём тонет.

## Решение

Работаем только с PNG. Калибровка — из метаданных плюс детекция рамки осей.

## Отвергнуто

**Выгрузка сырого `.dat` со станции.** В 26 раз больше трафика и хранилища ради
выигрыша, который не наблюдаем на фоне RMS. Плюс раскатка на весь парк станций
и работа в трёх репозиториях. И главное — не работает на уже накопленной истории.

**Компактный «гребень» со станции (~36 КБ).** Привлекательно по размеру и снимает
зависимость от стиля рендера. Но требует тех же изменений в клиенте и сети,
и так же не покрывает историю. Разумный кандидат на будущее, не на сейчас.

## Следствия

- Работает на всех наблюдениях с первого дня, без изменений в клиенте и сети.
- **Зависимость от стиля рендера.** Смена вёрстки водопада в клиенте может
  сломать детекцию рамки. Смягчено тем, что ничего не хардкодится: рамка
  детектируется, colormap читается из самого изображения (см.
  [algorithms.md](../algorithms.md)).
- Наблюдения без `satnogs:wf-dat` непригодны. Покрытие по годам — открытый
  вопрос фазы 0.
- **Метаданных недостаточно для оси времени.** Разбор клиента показал, что
  границы оси — это метки первой и последней строки данных, а `tabs[0]`
  в PNG не попадает (замер: ≈0.28 с → ~56 Гц систематики, своей у каждого
  наблюдения). Ось времени калибруется по минутным делениям — проверено,
  работает точно. Это не отменяет решение, но добавляет обязательный шаг,
  см. [algorithms.md](../algorithms.md) §1.3.
- Три центральных канала синтетические (клиент убирает DC-выброс) —
  ровно там, где остаток доплера проходит через ноль вблизи TCA.
  Маскируются явно.

## Что изменилось после измерений

Решение осталось в силе, но два довода из таблицы выше оказались неверны,
а один запрет снят. Записано, чтобы никто не опирался на устаревшие цифры.

**«Работает на истории наблюдений» — неверно.** `satnogs:wf-dat` пишет только
клиент 2.2.x, появившийся около июля 2026:

| Период | С метаданными | Версии клиента |
|---|---|---|
| 2024-07 | 0 / 6 | 1.2.2 |
| 2025-07 | 0 / 6 | 1.2.8 |
| 2026-03 | 0 / 6 | 1.2.8, 2.1.0 |
| 2026-07-01 | 0 / 8 | 2.1.0, 1.2.8, 2.0.0 |
| 2026-07-20 | 6 / 8 | 2.2.0, 2.2.2 |

То есть «вся история» — это около месяца. На 67 свежих наблюдениях метаданные
есть у 62 (93%), остальные приходят со станций на 2.1.0 и 1.2.8.

Правильная формулировка преимущества: **работает на 93% текущих наблюдений
без единой правки вне этого репозитория и без ожидания раскатки парка.**

**Ограничение «клиент и сеть не трогаем» снято.** Решение сохраняется не потому,
что править нельзя, а потому что раскатка парка занимает месяцы: прошлая (2.2.x)
шла с июля по август и до конца не дошла. Проработанная альтернатива —
[011](011-spectrum-artifact.md), отложена.

**Разрешение на широкой полосе хуже, чем в таблице.** 93 Гц/пиксель верно
для 57.6 кГц, но встречается полоса 240 кГц, где пиксель даёт **400 Гц** —
это уже сопоставимо с RMS фита. Таких наблюдений около 1.5%.

**Запасного пути для наблюдений без метаданных нет:** `satnogs_rx_samp_rate`
станции через API не отдаётся, полоса невосстановима в принципе. Такие
наблюдения помечаются непригодными.

**Хорошая новость:** `_gaussian_blur2d` в клиенте определён, но не вызывается —
мёртвый код. Единственная модификация спектра перед отрисовкой это зануление
трёх DC-каналов, поэтому картинка достаточно честный рендер.
