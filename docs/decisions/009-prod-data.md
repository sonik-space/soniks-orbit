# 009. Сервис работает с боевыми данными, UI на dev2

## Контекст

UI решено делать FSD-слайсом внутри `soniks-frontend` — там уже есть ui-kit, темы,
i18n, генерируемый клиент API и сущности `observation` / `station`, так что
дизайн-систему дублировать не пришлось бы. Фронтенд развёрнут на `dev2.sonik.space`
и подтягивает водопады из боевого бакета `sonics-data-prod`.

### Найденное противоречие

Три решения по отдельности выглядели разумно, а вместе не сходились:

- выбрана минимальная правка монолита, **чтобы фича работала до переезда**;
- UI живёт на dev2;
- но `scripts/etl/*` в `soniks-backend` показывают схему «дамп боевой БД →
  rsync на dev2 → восстановление», то есть **dev2 работает на снимке-реплике**.

TLE, опубликованное на реплике, до планирования боевой сети не доедет. Значит
главная ценность сценария уточнения — быстро навести сеть на свежий спутник —
до переезда всё равно не работала бы.

## Решение

Раздел на dev2 — **только UI**. Все данные раздела (наблюдения, водопады, TLE)
сервис берёт из **боевого Django** и туда же публикует. Реплика v2 в работе
сервиса не участвует.

После переезда меняется только адаптер `NetworkApi`.

## Отвергнуто

**До переезда без публикации.** Раздел на dev2 работает на реплике как расчётный
инструмент и отдаёт файл, автопубликация — только после v2. Монолит не трогаем
вообще, но сценарий уточнения ждёт месяцы.

**UI отдельным Next-приложением на проде.** И UI, и данные боевые, без раздвоения.
Но дублируются ui-kit, темы и i18n, а потом всё равно сливать в `soniks-frontend`.

## Следствия

- Сервис ходит в боевой API. Чтение публичное, запись — по правам.
- Нужен дисковый кеш скачанных PNG по `observation_id`: файлы неизменяемы,
  а нагрузка на S3 иначе избыточна.
- Надо проверить, нет ли лимита частоты запросов, который выбьет идентификация
  масштаба каталога.
- В разделе на dev2 данные боевые, а в остальном интерфейсе dev2 — из реплики.
  Расхождение допустимо, но раздел должен брать **всё** из своего сервиса,
  а не смешивать источники: иначе имя станции у наблюдения может отличаться
  от имени той же станции этажом выше.
