# 005. Отдельный сервис на стеке v2

> **Это решение заменяет более раннее суждение.** Сначала рекомендовалось писать
> Django-приложение внутри `soniks-network`. Разбор сохранён ниже, потому что
> без него та же идея вернётся: аргументы за неё выглядят убедительно, пока
> не учтён срок жизни монолита.

## Контекст

СОНИКС существует в двух видах:

- **Django-монолит** `soniks-network` — боевой `sonik.space`. Python 3.9,
  Django 4.0. **Выключается через несколько месяцев.**
- **`soniks-backend` (soniks-v2)** — FastAPI, Python 3.12, SQLAlchemy 2 async,
  dishka, taskiq + RabbitMQ, Keycloak JWT. Развёрнут на `dev2.sonik.space`,
  разрабатывается параллельно.

## Первоначальное суждение и почему оно неверно

Аргумент был такой: в монолите **уже стоит всё нужное** — `numpy 2.0.2`,
`scipy 1.13.1`, `sgp4 2.24`, `Pillow`, плюс Celery и Redis. Новых зависимостей ноль,
прямой доступ к моделям без HTTP, готовые авторизация, права, i18n, шаблоны и деплой.
Отдельный сервис при этом потребовал бы заново строить аутентификацию, тянуть
данные по HTTP и заводить write-эндпоинт.

Всё это верно и всё это не имеет значения: **приложение писалось бы в кодовую базу,
которую выключают.** Получился бы код на выброс плюс последующий перенос.

## Решение

Отдельный сервис, написанный **на стеке v2**: FastAPI, Python 3.12,
SQLAlchemy async, taskiq, той же структурой каталогов, что `soniks-backend`.

Работает уже сейчас поверх боевого Django-API. Позже либо втягивается в v2
почти копипастой, либо остаётся отдельным — оба варианта дёшевы.

## Отвергнуто

**Django-приложение в монолите.** См. выше — код на выброс.

**Сразу модулем внутри `soniks-backend`.** Правильный дом в конечном счёте
и никакого адаптера к старому API. Но пользователи увидели бы фичу только после
всей миграции, а разработка шла бы в ветку, которая сама активно меняется.

**Микросервис только для счёта, UI и хранение в Django.** Развязал бы версии
Python, но добавил сетевой хоп там, где хватило бы `import`, и всё равно оставил
бы UI в умирающем монолите.

## Следствия

- Ничего не пишется на выброс: сервис изначально на целевом стеке.
- Цена — **адаптер к API делается дважды**: сегодня Django, потом v2. Это тонкий
  слой за интерфейсом `NetworkApi`, десятки строк. См.
  [integration.md](../integration.md).
- Расчётное ядро вообще без фреймворка (правило 1), поэтому переезд его не касается.
- Монолит трогается минимально, см. [008](008-minimal-monolith-pr.md).
- Аутентификация делается один раз: Keycloak уже общий для монолита
  (`mozilla-django-oidc`) и для v2.
