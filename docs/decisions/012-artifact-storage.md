# 012. Артефакт уходит прямо в soniks-orbit

> **ОТЛОЖЕНО вместе с [011](011-spectrum-artifact.md).** Артефактов сейчас нет,
> поэтому хранить нечего. Разбор сохранён: при возврате к артефактам это
> первый вопрос, который придётся решать.

## Контекст

Решение [011](011-spectrum-artifact.md) добавляет новый файл на каждое наблюдение.
Его надо где-то хранить.

Модель наблюдения в СОНИКС знает только о двух файлах — аудио и водопаде.
Приложение `artifacts` из апстрима SatNOGS в форк не портировали, то есть
подходящего места просто нет.

## Решение

Клиент отправляет артефакт **отдельным эндпоинтом прямо в `soniks-orbit`**,
у которого уже есть собственные база и хранилище. Модель сети не трогается вообще.

## Отвергнуто

**Завести артефакт в сети — и в Django, и в v2.** Правильный дом: артефакт
логически часть наблюдения, виден со страницы, переживает любой сервис.
Но это новая модель, миграция, эндпоинт загрузки и настройка хранилища
в монолите, который выключают, — прямое нарушение
[008](008-minimal-monolith-pr.md), причём куда крупнее остальных четырёх правок
вместе взятых.

**Завести артефакт только в v2.** Архитектурно чисто и без работы в умирающем
монолите. Но тогда раздел заработает только после запуска v2 в прод, а это
отменяет [009](009-prod-data.md) — «фича работает с боевыми данными до переезда».

## Следствия

- **Клиент начинает ходить в два адреса.** Нужен отдельный адрес в настройках,
  своя аутентификация и очередь повторов. У клиента уже есть конвейер отправки
  (`jobs/sending_data.py`), так что это добавление цели, а не новый механизм.
- **Артефакт не виден со страницы наблюдения** в СОНИКС. Приемлемо: это
  служебные данные для одного инструмента, а не результат наблюдения.
- **Потеря артефакта не критична.** Водопад и аудио по-прежнему уходят в сеть
  штатным путём. Если сервис недоступен, теряется только возможность
  определить орбиту по этому проходу.
- Сервису нужно собственное объектное хранилище и правило удаления старых
  артефактов — они нужны, пока идёт работа с наблюдением, а не вечно.
- Аутентификация станции: у клиента уже есть `client_id`, которым он
  представляется сети. Сервис проверяет станцию через API СОНИКС,
  собственного реестра станций не заводит.
- **При переезде на v2 это стоит пересмотреть.** Там артефакты имеет смысл
  завести штатно, и тогда сервис станет читателем, а не хранилищем.
