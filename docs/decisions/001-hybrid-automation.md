# 001. Гибридная автоматизация

## Контекст

В текущем процессе человек кликает мышью **каждую** точку доплеровского трека
на водопаде. Десятки кликов на наблюдение, умножить на 5–10 наблюдений — это
основная трудоёмкость всей процедуры.

При этом сигнал на водопаде — яркий гребень на тёмном фоне, то есть задача
поддаётся автоматическому извлечению.

## Решение

Сервис извлекает трек автоматически и показывает результат поверх водопада.
Человек удаляет мусор и дорисовывает пропуски. Фит запускает человек и видит
RMS и невязки.

## Отвергнуто

**Только ручные клики (точный веб-порт).** Меньше кода и нулевой риск, что
автомат наврёт. Но трудоёмкость для пользователя не падает — исчезает только
необходимость ставить софт. Заявленная цель раздела при этом не достигается.

**Полный автомат, кнопка «получить TLE».** Максимум удобства, но на слабых
и обрывочных сигналах — а это типичный случай именно для спутника с неизвестной
орбитой — молча выдавал бы мусор. Правдоподобный неверный результат хуже, чем
отсутствие результата.

## Следствия

- Нужен алгоритм извлечения гребня со списком известных режимов отказа
  (см. [algorithms.md](../algorithms.md)).
- Нужен полноценный редактор точек в UI, а не только просмотр.
- **Пустой результат извлечения — нормальное состояние**, а не ошибка.
  Если UI подаёт его как поломку, оператор решит, что инструмент сломан,
  вместо того чтобы разметить руками, и гибридная схема не сработает.
- Ручной режим остаётся полноценным запасным путём для любого наблюдения.
