# Интеграция с СОНИКС

Сейчас СОНИКС — Django-монолит на `sonik.space`. Параллельно разрабатывается v2
(FastAPI, `soniks-backend`), развёрнутый на `dev2.sonik.space`. Переход ожидается
через несколько месяцев.

Сервис работает с **боевым Django**, а не с dev2: на dev2 стоит ETL-реплика
(`scripts/etl/*` — дамп прода, rsync, восстановление), и опубликованное там TLE
не дошло бы до планирования наблюдений реальной сети.
См. [decisions/009-prod-data.md](decisions/009-prod-data.md).

---

## Изоляция

Всё, что специфично для текущего API, спрятано за одним интерфейсом:

```
application/interfaces/network_api.py     ← контракт
infrastructure/network_api/django.py      ← сегодня
infrastructure/network_api/v2.py          ← после переезда
```

Контракт формулируется в терминах предметной области, а не в терминах эндпоинтов:

```python
class NetworkApi(Protocol):
    async def get_observation(self, observation_id: int) -> dict: ...
    def iter_observations(self, **params) -> AsyncIterator[dict]: ...
    async def get_transmitter(self, uuid: str) -> dict | None: ...
    async def publish_tle(self, *, norad_id: int, lines: TleLines,
                          url: str, access_token: str) -> int: ...
    # фаза 6, ещё не написан:
    # async def list_launch_objects(self, intdes: str) -> list[CatalogObject]: ...
```

`publish_tle` **не принимает источник записи**: его назначает монолит. Раз выбор
источника решает, чьи элементы поведут сеть, право его назначать не отдаётся
тому, кто присылает строки.

`access_token` — токен человека, с которым пришёл запрос: публикация идёт
от его имени, права проверяет сеть, своей модели прав сервис не держит.

`get_latest_tle` **не заведён**: сценария, который бы его звал, в фазе 5 нет,
а интерфейс растёт по мере появления сценариев (правило 12).

Переезд на v2 — одна новая реализация этого протокола.

**`get_observation` возвращает сырой словарь, а не `ObservationSnapshot`.**
Здесь раньше стоял разобранный тип, и он избыточен: ответ целиком
замораживается в `od_session_observations.meta` (правило 10), то есть словарь
всё равно доезжает до хранения нетронутым, а типизированная обёртка добавила бы
второе представление тех же данных и мэппер между ними. Заводить её имеет смысл
тогда, когда появится вторая реализация протокола и станет видно, какие поля
у Django и у v2 называются по-разному.

Методы объявляются по мере появления сценариев, а не заранее (правило 12):
на фазу 2 их три.

## Что читаем сегодня

### `GET /api/observations/{id}/`

Публичный, без авторизации. Отдаёт всё нужное одним запросом:

| Поле | Зачем |
|---|---|
| `tle` → `{tle0, tle1, tle2, updated, tle_source}` | опорное TLE для снятия доплера и затравка |
| `station_lat`, `station_lng`, `station_alt` | положение наблюдателя. **Высота в метрах** |
| `ground_station` | id станции |
| `observation_frequency` | центральная частота, Гц |
| `waterfall` | абсолютный URL PNG |
| `start`, `end`, `norad_cat_id`, `vetted_status`, `waterfall_status` | |

**TLE берётся отсюда, а не выскребается регуляркой со страницы наблюдения** —
именно так делали оба старых инструмента, и это ломается при любой правке шаблона.

Ответ целиком замораживается в `od_session_observations.meta` (правило 10).

### `GET /api/observations/?...`

Список для подбора наблюдений. Курсорная пагинация, тело — голый массив,
ссылки в заголовке `Link`.

### Водопад

Скачивается по URL из `waterfall`, публичный S3. Файлы неизменяемы, поэтому
кешируются на диске по `observation_id`.

Наблюдения без `satnogs:wf-dat` в метаданных PNG непригодны: полоса
невосстановима, поле `satnogs_rx_samp_rate` станции через API не отдаётся.
Это вся история до июля 2026 и станции на клиентах старше 2.2.x.

### Каталог для идентификации

Объекты запуска — через `Launch` / INTDES (СОНИКС уже тянет их из Celestrak
по `gp.php?INTDES=`). Полный активный каталог — кеш в `infrastructure/catalog/`.

## Что пишем

### `POST /api/tles/` — новый эндпоинт

Сегодня `/api/tles/` только на чтение, поэтому публикация требует правки монолита.
Обойти это можно было бы только записью напрямую в чужую БД, что хуже.

Тело: номер объекта, три строки TLE и `url` со ссылкой на прогон фита.
Источник записи — **`Manual`**, и ставит его сервер монолита.

Реализация **переиспользует готовое**, а не пишет заново:

- `network/base/tasks.py::validate_tle` — контрольные суммы, согласованность номера
  в обеих строках, диапазоны элементов, положительные перигей и апогей;
- `network/base/tle_priority.py::refresh_latest_tle_sets` — обновление `LatestTleSet`;
- `network/base/tle_utils.py` — alpha-5 и OMM.

Аутентификация: `mozilla_django_oidc.contrib.drf.OIDCAuthentication`
**на этом вьюсете**, а не в `DEFAULT_AUTHENTICATION_CLASSES`. Сегодня в DRF
монолита нет ни одного класса, понимающего Keycloak-токен, а глобальная правка
меняла бы аутентификацию всего `/api/`.

Права: `Satellite.created_by` либо группа `Operators` / `Moderators`
(`network/base/perms.py::publish_tle_perms`). Связи «пользователь ↔ спутник»
в монолите нет — `Operator` это плоский справочник без ссылки на `User`, —
поэтому формулировка «владелец или оператор» заменена на то, что есть,
и это записано в [decisions/007](decisions/007-publishing.md).

Отказ по правам сервис превращает в предложение: `mode` в ответе становится
`propose`, `published_tle_id` остаётся `null`, в каталог ничего не уходит.

### Провенанс

Под источником `Manual` публикация фита в каталоге **неотличима от ручной
строки**. Происхождение живёт в двух местах:

- `Tle.url` — ссылка на прогон фита, единственный признак на стороне Django;
- `GET /api/v1/publications` у сервиса — админ-вид «опубликованные за 7 дней»
  со спутником, RMS, числом точек, режимом, автором и id записи в каталоге.

Второе и есть тот админ-вид, который [decisions/007](decisions/007-publishing.md)
требует **до** первой боевой публикации.

## Приоритет источника

`network/base/tle_priority.py` **не правится**:

```python
TLE_SOURCE_PRIORITY = ["Manual", "SpaceTrack", "Celestrak", "SatNOGS"]
```

`Manual` в нём уже первый, поэтому свежая публикация выигрывает
`select_latest_tle` без единой строки правки. Отдельного источника `Fitted`,
посточникового окна свежести и замера на боевых данных перед выкаткой
не требуется — они отменены вместе с [decisions/010](decisions/010-fitted-priority.md).

Цена названа прямо: фит перебивает не только протухший, но и **свежий**
Space-Track. Вся защита каталога переехала на порог качества
в `application/commands/fit/publish.py` (правило 11).

## Полный список правок монолита

Намеренно минимальный: монолит выключают. После разведки фазы 5 их **одна**,
а не четыре:

1. `network/api/` — `POST /api/tles/` с проверкой прав и OIDC на вьюсете.

Отпало и почему:

| Отклонено | Чем закрыто |
|---|---|
| `"Fitted"` в `TLE_SOURCE_PRIORITY` | публикуем как `Manual`, он уже первый |
| Посточниковое окно свежести | не нужно без отдельного источника |
| `list_filter` в `TleAdmin` | админ-вид переехал в `GET /api/v1/publications` |
| Ссылка на раздел со страницы наблюдения | чистое удобство; провенанс уехал в `Tle.url` |
| `location /tle/` в nginx | конфигурации nginx в репозитории монолита нет вовсе — задача эксплуатации |

Эндпоинт `/api/me/` **не нужен**: аутентификация идёт через Keycloak, который уже
общий — в монолите стоит `mozilla-django-oidc` (`network/oidc.py`), в v2
настроен `AUTH__KEYCLOAK__*`. Сервис валидирует JWT сам, одинаково до и после переезда.

## Аутентификация

Keycloak JWT. Валидация копируется из `soniks-backend/src/presentation/api/auth/`.
`sub` из токена — владелец сессии (`owner_sub`).

Права на публикацию проверяются на стороне СОНИКС при вызове `POST /api/tles/`:
сервис не хранит собственной модели прав и не дублирует роли. Для этого
в `publish_tle` уходит **тот же токен**, с которым пришёл запрос, — публикация
идёт от имени человека, а не сервиса.

## Что проверить перед боевым запуском

- Нет ли лимита частоты запросов, который выбьет идентификация масштаба каталога
  или массовое создание сессий.
- Приемлема ли нагрузка на S3 от скачивания водопадов (кеш обязателен).
- Админ-вид «опубликованные за 7 дней» — `GET /api/v1/publications`,
  до первой боевой публикации.
- Что группа `Operators` или `Moderators` действительно выдана тем, кто будет
  публиковать: иначе всё уйдёт в предложения, и это будет выглядеть поломкой.
- Что `OIDC_OP_USER_ENDPOINT` в монолите настроен: без него `OIDCAuthentication`
  не примет ни одного токена, а сервис получит `403` на каждой публикации
  и молча превратит её в предложение.
