## Как радионаблюдение превращается в орбиту

Станция принимает сигнал спутника на известной частоте. Спутник движется, поэтому
принимаемая частота смещена эффектом Доплера:

```
f_принятая = f_передатчика · (1 − v_r / c)
```

где `v_r` — **лучевая скорость**, проекция скорости спутника относительно станции
на направление «станция → спутник». Приближается — `v_r < 0`, частота выше;
удаляется — `v_r > 0`, частота ниже.

За проход `v_r` меняется от −7 км/с через ноль до +7 км/с, и частота рисует
характерную **S-кривую**: почти плоско, резкий спад, снова почти плоско.
Точка перегиба — момент наибольшего сближения (**TCA**, time of closest approach).

Обратная задача: по форме этой кривой восстановить орбиту. Форма даёт две величины —
когда был TCA (положение спутника вдоль трассы) и насколько крут перегиб
(дальность в TCA, то есть насколько высоко над горизонтом прошёл спутник).

**Из одного прохода наблюдаемы примерно две величины.** Шесть элементов орбиты
из них не восстановить. Отсюда всё устройство фита: см.
[algorithms.md](algorithms.md), раздел про приоры.

## Водопад

Спектрограмма наблюдения: по горизонтали частота, по вертикали время (снизу вверх),
яркостью — мощность. Строится клиентом станции и хранится в СОНИКС **только
как отрендеренный PNG** — сырых спектральных данных сеть не хранит.

Поэтому сервис работает с пикселями картинки: калибровка берётся из метаданных
PNG, рамка осей детектируется, яркость восстанавливается по colorbar.
См. [decisions/002](decisions/002-pixel-only.md); проработанная альтернатива
с выгрузкой спектра со станции отложена — [decisions/011](decisions/011-spectrum-artifact.md).

Существенно: **клиент снимает доплеровскую коррекцию во время записи.** Он ведёт
приёмник по предсказанию из известного TLE, поэтому по оси частот на водопаде
отложен не сам доплер, а **остаток** — расхождение между реальностью и предсказанием.
Хороший TLE даёт почти вертикальную линию, плохой — заметную кривую.

Чтобы получить абсолютную частоту, доплер по опорному TLE нужно **вернуть обратно**:

```
f_abs = f_центра + f_смещение(t) − f_центра · v_r(t)/c
```

Здесь `v_r` считается по тому TLE, которое было у наблюдения в момент записи —
поэтому оно замораживается, см. правило 10 в
[ai-development-rules.md](ai-development-rules.md).

## TLE и элементы орбиты

**TLE** (two-line element set) — две строки ровно по 69 символов с контрольной суммой.
Кодируют семь величин плюс эпоху:

| Элемент | Обозначение | Что это |
|---|---|---|
| Наклонение | `i`, incl | угол плоскости орбиты к экватору, град |
| Долгота восходящего узла | `RAAN`, `Ω` | поворот плоскости орбиты, град |
| Эксцентриситет | `e`, ecc | вытянутость; 0 — окружность |
| Аргумент перигея | `argp`, `ω` | поворот эллипса в своей плоскости, град |
| Средняя аномалия | `M` | положение спутника по орбите на эпоху, град |
| Среднее движение | `n` | оборотов в сутки |
| Баллистический коэффициент | `B*` | торможение атмосферой |

**Эпоха** — момент, к которому относятся элементы, в формате `YYDDD.dddddddd`
(две цифры года, день года с дробной частью). Например `26005.391632` —
2026 год, 5-й день, 09:23:57 UTC.

TLE — это **средние** элементы модели SGP4, а не мгновенные (оскулирующие).
Их нельзя подставлять в формулы двух тел напрямую; они имеют смысл только
вместе с SGP4. Это важно для переноса эпохи, см. ниже.

### Вырождение при круговой орбите

При `e ≈ 0` перигея физически нет, поэтому `argp` и `M` по отдельности бессмысленны:
их можно менять в противоположные стороны, и орбита не изменится. Определена только
**сумма** `argp + M` (аргумент широты). Фит обязан это учитывать, иначе он будет
хаотично гонять оба параметра, показывая правдоподобный RMS и бессмысленные элементы.

Почти все наблюдаемые сетью спутники — на околокруговых орбитах.

## Перенос эпохи

Уточнённое TLE относится к какой-то эпохе. Чтобы отнести его к другому моменту
(обычно к последнему наблюдению), нельзя просто переписать поле эпохи —
элементы при этом останутся от старого момента.

Нужно: пропагировать состояние SGP4 вперёд до целевого момента, получить положение
и скорость, а затем **обратить** их в средние элементы. Обращение неаналитическое,
делается неподвижной точкой за несколько итераций.

Именно это делал `propagate` из sattools. В `rffit` клавиша `e` переписывает только
поле эпохи, не трогая элементы — поэтому в гайде после `w` обязательно шёл `propagate`.

## Невязка, RMS, несущая

**Модель** предсказывает частоту в момент `t_i` при данных элементах:
`f_модель = (1 − v_r(t_i)/c) · F`, где `F` — истинная частота передатчика.

**Невязка** — разность измеренной и модельной частоты, в кГц.
**RMS** — корень из среднего квадрата невязок. Это главное число, по которому
оценивается фит. Хороший фит по нескольким проходам — единицы сотен Гц.

**Несущая `F`** заранее неизвестна: паспортная частота передатчика отличается
от реальной. Но при фиксированных элементах оптимальная `F` находится
в замкнутом виде обычным МНК — поэтому она не входит в оптимизацию,
а вычисляется на каждой итерации (**профилируется**).

Более того, `F` **своя у каждого наблюдения**: погрешность опорного генератора
станции (±1–3 ppm — это ±0.4–1.3 кГц на 435 МГц) и температурный уход передатчика
дают сдвиг, свой для каждого прохода. В `rffit` несущая одна на весь набор,
и оператору приходилось выравнивать каждое наблюдение вручную клавишей `m`.
Мы делаем несущую отдельной на наблюдение, и ручной шаг исчезает —
см. [decisions/003-fit-engine.md](decisions/003-fit-engine.md).

Расхождение `F` между проходами само по себе информативно: большой разброс
означает проблему со станцией или с передатчиком, и его надо показывать.

**Затравка** (seed) — исходное TLE, от которого стартует фит.

## Идентификация

После кластерного запуска в каталоге появляются десятки объектов, и неизвестно,
какой из них твой. Задача: по принятому сигналу определить, какому каталожному
объекту он соответствует.

Решается перебором: для каждого кандидата профилируется несущая (без фита элементов!)
и считается RMS. Правильный объект даёт RMS на порядок меньше остальных.
Дёшево, потому что на кандидата нужна одна прогонка SGP4 по точкам трека.

В `rffit` это была клавиша `i`.

## Глоссарий

| Термин | Значение |
|---|---|
| **MJD** | Modified Julian Date, суток от 1858-11-17. Внутренний формат времени |
| **TCA** | Time of Closest Approach, момент наибольшего сближения |
| **SGP4** | стандартная модель движения, для которой определены TLE |
| **Оскулирующие элементы** | мгновенные, из положения и скорости |
| **Средние элементы** | усреднённые по короткопериодическим возмущениям; это и есть TLE |
| **NORAD ID** | номер объекта в каталоге; выше 99999 кодируется схемой alpha-5 |
| **COSPAR / INTDES** | международное обозначение, `YYYY-NNNAAA`; общее для одного запуска |
| **Alpha-5** | кодирование 6-значных номеров буквой в первой позиции |
| **OMM** | XML/JSON-формат элементов, современная замена TLE |
| **Лучевая скорость** | `range rate`, проекция скорости на луч «станция → спутник» |
| **Профилирование параметра** | исключение из оптимизации через аналитическое решение |
| **Приор** | член в невязках, штрафующий отход от затравки |
| **Гребень** | яркая линия сигнала на водопаде |
| **Проход** | один сеанс видимости спутника станцией; одно наблюдение |
| **Затравка / seed** | исходное TLE, от которого стартует фит |
| **Водопад** | спектрограмма наблюдения, PNG |
| **`.dat` strf** | формат точек: `MJD  частота_Гц  вес  id_станции` |
