# Правила разработки

Этот файл — главный. Разработка идёт в разных сессиях, у каждой свой контекст,
и всё, что здесь не записано, будет забыто и переизобретено по-другому.

Правила ниже — не стилистические предпочтения. Каждое соответствует конкретному
способу сломать проект тихо, так что поломка всплывёт через недели.

---

## 1. Чистота ядра

`src/domain/od/` и `src/domain/waterfall/` не импортируют **ничего**, кроме
stdlib, `numpy`, `scipy`, `sgp4`.

Запрещены, в частности: `fastapi`, `sqlalchemy`, `httpx`, `pydantic`, `PIL`,
`dishka`, любые модули из `src/infrastructure`, `src/application`, `src/presentation`.

Ядро принимает `np.ndarray` и `dict`, а не байты, не URL, не ORM-объекты.
Декодирование PNG — это инфраструктура (`infrastructure/images/loader.py`),
а не часть алгоритма.

**Зачем.** Ядро — единственная часть, которая переживёт переезд на v2 без изменений.
Оно же должно гоняться из голого скрипта в фазе 0 и из тестов без поднятия БД.
Один импорт `sqlalchemy` в `fit.py` — и ядро перестаёт быть портируемым.

Проверяется тестом `tests/unit/test_core_purity.py`, который парсит AST всех файлов
в `domain/od` и `domain/waterfall` и падает на запрещённом импорте. Не удалять.

## 2. Единицы измерения

Самый вероятный источник тихих ошибок в этом проекте. Границы пересекаются постоянно,
и ошибка в 1000 раз не всегда заметна на графике.

| Величина | В ядре | В хранении и API | Во внешних источниках |
|---|---|---|---|
| Частота | **кГц** в векторе невязок (как в `rffit`) | **Гц** | Гц в Django API, кГц на оси водопада |
| Время | **MJD** (float) | ISO 8601 UTC | ISO в Django API, MJD в `.dat` strf |
| Высота станции | **км** | метры | **метры** в Django API, **км** в `sites.txt` strf |
| Скорость | км/с | — | км/с в strf |
| Углы | градусы в элементах, радианы внутри SGP4 | градусы | градусы в TLE |

**Правило именования: единица входит в имя переменной на каждом пересечении границы.**
`f_khz`, `f_hz`, `alt_km`, `alt_m`, `v_km_s`, `t_mjd`, `t_iso`.
Переменная `freq` без суффикса в коде, работающем с частотами, — это дефект,
даже если сейчас она верна.

`domain/od/constants.py` — единственное место, где живут константы:
`C_KM_S = 299792.458`, `XKMPER = 6378.137`, `FLAT = 1/298.257`.
Значения взяты из `strf/rffit.c` намеренно, чтобы регрессионный тест сходился.
Не «уточнять» их по справочнику — это сломает сверку с эталоном.

## 3. `rffit` — эталон, а не легенда

`strf/rffit.c` — работающая реализация, проверенная годами наблюдений.
Наш фит должен воспроизводить её в режиме совместимости
(одна глобальная несущая, приоры выключены, `loss='linear'`).

Любое расхождение сначала **объясняется**, потом принимается. Формулировка
«ну, у нас немного другая математика» недопустима: она означает, что мы не знаем,
где ошиблись — в порте или в улучшении.

Порядок отладки расхождения — строго снизу вверх по лестнице из
[testing.md](testing.md): сначала `range_rate`, потом несущая, потом фит.
Расхождение, найденное сразу на уровне фита, неотлаживаемо.

Ожидаемое исключение: `strf/sgdp4.c` — более старый порт SGP4, чем `python-sgp4`
(Vallado 2006). Разница по `range_rate` до ~1e-5 км/с нормальна и объяснима.
Больше — это наша ошибка, а не разница реализаций.

## 4. Что не портируем из старых инструментов

В `soniks-waterfall-tabulation-helper`, `ikhnosoniks` и форке `strf` есть дефекты.
Они разобраны и **не должны воспроизводиться**:

| Дефект | Где | Как правильно |
|---|---|---|
| TLE выскребается регуляркой из HTML страницы наблюдения | оба питон-инструмента | брать `obs["tle"]` из JSON API |
| Геометрия водопада захардкожена `(66,1553)-(686,13)` | tabulation-helper | детектировать рамку осей, см. `algorithms.md` |
| Полоса угадывается: `48e3`, для одного NORAD `230.4e3` | tabulation-helper | `samp_rate` из метаданных PNG |
| Регулярка на кириллическое `Гц` против сравнения с латинским `'G'` → ГГц читается в 1000 раз мимо | `ikhnos.py` | не парсить частоту со страницы вообще |
| Оверлей вставляется в `(0,0)` без выравнивания по осям | `ikhnos.py` | рисовать по калибровке |
| `sprintf` затирает корректный путь к `sites.txt`, плюс `printf(filename)` | форк `strf/rfsites.c` | не тащить этот патч |
| `logger.debug(line, end=...)` — у `Logger.debug` нет такого аргумента | tabulation-helper | — |
| `strptime` падает на метках без долей секунды | оба | парсить время устойчиво |

Если понадобилось скопировать код из старых инструментов — сначала свериться
с этой таблицей.

## 5. Тесты

Нетривиальная логика (ветвление, цикл, парсер, любая математика) оставляет после себя
**один запускаемый тест** — наименьший, который упадёт, если логика сломается.
Без фикстур, без фреймворков сверх `pytest`, без тестов на каждую функцию.

Тривиальные однострочники не тестируются.

Обязательные и неудаляемые:

- `tests/unit/test_core_purity.py` — правило 1;
- `tests/regression/` — сверка с `rffit` по golden JSON;
- `tests/golden/` — извлечение трека на реальных водопадах.

Golden-файлы обновляются **только** осознанно, отдельным коммитом, с объяснением
в сообщении коммита, почему эталон изменился. Обновление golden ради зелёного CI —
это удаление теста.

## 6. Сознательные упрощения помечаются

Там, где выбран заведомо неполный вариант с известным потолком, ставится комментарий:

```python
# ponytail: JSONB-блок вместо таблицы точек; SQL по отдельным точкам невозможен.
#           Разносить, если понадобится поточечная аналитика.
```

Формат: `ponytail:` + в чём потолок + при каком условии апгрейдить.

Уже принятые упрощения, которые должны быть помечены в коде:

1. Точки трека в JSONB колонками-массивами, а не таблицей.
2. RANSAC-кубика вместо динамического программирования при трассировке гребня.
3. Несущая профилируется по весам качества, без внутреннего IRLS под `soft_l1`.
4. Бистатика (`rsite_id`, GRAVES) не портируется.
5. Один `domain/models.py` вместо развесистой структуры агрегатов из `soniks-backend`.
6. Работаем с пикселями PNG, а не с выгрузкой спектра со станции
   (альтернатива проработана и отложена — [decisions/011](decisions/011-spectrum-artifact.md)).

Это не список долгов «когда-нибудь исправить». Это список мест, где ответ на вопрос
«почему так примитивно?» уже дан, и переспрашивать не нужно.

## 7. Roadmap обновляется тем же коммитом

`docs/roadmap.md` меняется в том же коммите, что и код. Иначе следующая сессия
не знает, где остановились, и начинает с того, что уже сделано.

Если задача оказалась сложнее, чем описано, — правится описание задачи,
а не только чекбокс.

---

## 8. Границы слоёв

```
presentation  → application  → domain
infrastructure → (реализует интерфейсы из application/interfaces)
```

- `presentation/` — только разбор запроса, вызов команды/запроса, сборка ответа.
  Никакой логики.
- `application/` — оркестрация. Знает про `domain` и про **интерфейсы**
  инфраструктуры, но не про `httpx`, `sqlalchemy`, `PIL`.
- `application/services/calibration.py` — **единственное** место, где сшиваются
  загрузка PNG → декодирование → калибровка → извлечение → снятие доплера.
  Если эта цепочка появилась где-то ещё, это ошибка.
- `infrastructure/` — реализации: HTTP-клиент к СОНИКС, PIL, репозитории, taskiq.
- `domain/` — правило 1.

## 9. Эфемериды считаются только на сервере

Фронтенд **никогда** не вычисляет доплер, не превращает пиксель в абсолютную
частоту и не анализирует картинку водопада.
Ручная точка отправляется как `f_offset_hz` (смещение от центра), а `f_abs_hz`
заполняет сервер.

**Зачем.** Иначе появляются две реализации снятия доплер-коррекции — на Python
и на `satellite.js` — которые обязательно разойдутся, и расхождение проявится
как необъяснимый вклад в невязки у точек, поставленных руками.

Фронтенду разрешено считать SGP4 только для декоративных целей
(например, отрисовать модельную кривую между запросами), и такие места помечаются
комментарием, что это не источник истины.

## 10. Данные наблюдения замораживаются

При извлечении трека ответ Django API целиком сохраняется в
`od_session_observations.meta`, включая TLE, по которому снималась доплер-коррекция.

**Зачем.** TLE в каталоге обновляется каждые 4 часа. Если пересчитать позже
по новому TLE, изменится смысл уже посчитанных `f_abs_hz`, и опубликованное TLE
станет невоспроизводимым. Замороженный снимок — единственное, что делает
публикацию проверяемой.

---

## 11. Публикация в каталог — операция с радиусом поражения

Плохое TLE, выигравшее `select_latest_tle` в СОНИКС, ломает наведение **всей сети**
по этому спутнику и утекает наружу через публичный фид `/api/latesttles/`.

Публикация идёт под источником **`Manual`**, а он **первый** в
`TLE_SOURCE_PRIORITY`. Значит свежая публикация перебивает не только протухший,
но и свежий Space-Track, причём немедленно. Отдельного источника с более низким
приоритетом нет, посточникового окна свежести нет, ступени между «нажал кнопку»
и «сеть наводится по этим элементам» нет тоже.

**Порог качества в `application/commands/fit/publish.py` — не одна из защит,
а единственная.** Пять условий: прогон сошёлся, RMS ≤ 1.0 кГц, точек ≥ 100,
наблюдений ≥ 2, расхождение положения с затравкой на эпохе ≤ 50 км.

Отсюда два запрета:

- **Значения живут константами модуля, а не в конфигурации.** Порог, вынесенный
  в переменную окружения, ослабляется без единой правки кода и без следа
  в документации — ровно то, что запрещает следующий пункт.
- **Ослаблять значения можно только вместе с правкой**
  [decisions/007-publishing.md](decisions/007-publishing.md), где записано,
  почему выбраны именно эти числа и какая защита была сознательно снята
  в обмен на одну правку монолита вместо трёх.

Порог проверяется **до** обращения к Django, а не после: отказ каталога — это
уже последствие, а не проверка.

---

## 12. Стиль

- Python 3.12, `ruff` с конфигурацией из `soniks-backend`, `uv` для зависимостей.
- Аннотации типов обязательны в `domain/` и в интерфейсах `application/`.
- Комментарии на русском (как в `soniks-client`), идентификаторы на английском.
- Никаких абстракций «на будущее»: интерфейс с одной реализацией заводится только
  там, где он нужен для подмены в тестах или для будущей замены Django на v2.
